# HMS-AI-ROUTER — v25.75 P1 Guided UAC Operator Runner

Date: 2026-08-24

## Purpose

Reduce the authorized real-Windows UAC recovery validation from four manual Python commands to one guided operator flow without automating Windows consent.

## Entry points

- Double-click: `HMS_VALIDATE_UAC_RECOVERY.cmd`
- Direct PowerShell: `_runtime/HMS_Run_UAC_Validation.ps1`
- Proof-only: `_runtime/HMS_Run_UAC_Validation.ps1 -Proof`

The launcher uses normal `powershell.exe -NoLogo -NoProfile -File`. It does not use `runas`, `ExecutionPolicy Bypass`, keyboard automation, direct `taskkill`, or a direct process launcher.

## Guided sequence

The runner performs exactly this sequence:

1. Session `init` — read-only preflight and source/host/session binding.
2. Require the operator to type exact `CANCEL` before the first interactive case.
3. Run `run-cancel`; Windows displays the real UAC prompt and the operator must cancel it.
4. Require `PASS_CANCEL_AND_REPLAY_BLOCK` plus same-token replay rejection.
5. Require the operator to type exact `CLOSE` before the second interactive case.
6. Run `run-close`; Windows displays the real UAC prompt and the operator must accept it.
7. Require `PASS_CLOSE_AND_REPLAY_BLOCK`, same-token replay rejection and a positive supported-client close count.
8. Run session pair `verify` automatically.
9. Require final verdict `PASS_BOUNDED_UAC_RECOVERY_PAIR`.

Reports are stored under a timestamped directory beneath:

`%LOCALAPPDATA%\HMS-AI-ROUTER\uac-validation-v2575\`

The runner never accepts/cancels the UAC dialog for the user. Consent remains a human Windows action.

## Fail-closed behavior

The runner stops if:

- Windows is not the host OS;
- Python is unavailable;
- the validation bundle is missing;
- session preflight is blocked;
- exact operator acknowledgement is missing;
- Cancel or Close case does not produce its expected verdict;
- replay is not blocked;
- no supported process was actually closed in the Close case;
- session-pair verification fails;
- any report attempts to cross the non-production boundary.

## Windows CI proof

The Windows workflow now:

- parses the operator PowerShell helper;
- invokes its `-Proof` mode using **Windows PowerShell 5.1** (`shell: powershell`), not only PowerShell 7;
- checks the double-click launcher exists and calls the expected runner;
- rejects a launcher containing `runas` or `ExecutionPolicy Bypass`;
- verifies the runner contains no direct `Start-Process`, direct `taskkill`, or keyboard automation command;
- does not execute `init`, `run-cancel`, `run-close`, `verify`, a UAC prompt, or a real supported-client close.
