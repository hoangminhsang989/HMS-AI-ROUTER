## P0 completed in source

### Exact seven-case Windows/Codex evidence contract

- Canonical runtime cases remain exactly:
  `host`, `codex`, `quota`, `failover`, `lan`, `soak_6h`, `soak_24h`.
- This set is inherited from the v25.53 Target-Machine Certification `SAFE_STAGES`; v25.75 does not invent replacement IDs.
- External ingest rejects arbitrary seven-ID packets, missing IDs, unexpected IDs and duplicates.
- Seven-case exporter only derives case reports from a source report with:
  `PASS_TARGET_MACHINE_PRODUCTION_CERTIFIED`,
  `TARGET_MACHINE_WINDOWS_CODEX_LAN_SOAK`, exact 7/7 stages and all stages `pass=true`.
- Partial target reports cannot be upgraded into seven-case external evidence.

### Certificate-only external evidence signing

- External review packets no longer accept self-declared signer/trust JSON.
- External packet signer class is `WINDOWS_CERTIFICATE_SIGNATURE` only.
- v25.75 Windows helper `_runtime/HMS_Sign_Digest_With_Certificate.ps1` signs only with an RSA certificate private key in `Cert:\CurrentUser\My`; private key material is never exported.
- `_runtime/HMS_Codex_ExternalWindowsCertificateSigner.py` invokes the helper using canonical PowerShell named parameters and immediately self-verifies the resulting certificate signature.
- Packet signature binds all promotion-relevant packet fields except the signature envelope itself, including package SHA-256, release-manifest SHA-256, frozen Cockpit baseline, capture/run/nonce IDs, trust snapshot and exact seven case-report digests.
- Payload mutation after signing is rejected.
- DPAPI local-machine HMAC remains valid for its existing local attestation purposes but is explicitly insufficient for independent external packet review.

### Trust-store enrollment, revocation and independent trust anchor

- `_runtime/HMS_Codex_ExternalWindowsCertificateEnrollment.py` performs explicit operator enrollment: sign a non-evidence challenge, self-verify the certificate, derive certificate validity and pin the certificate into the existing HMS attestation trust store.
- Certificate pin state/rotation/revocation/validity uses `_runtime/HMS_Codex_AttestationTrustStore.py` authority.
- Public trust snapshots are deterministic for the same trust-store generation.
- The packet-carried trust snapshot is not allowed to be its own trust root.
- External ingest now requires `expected_trust_snapshot_sha256` supplied by reviewer/import authority independently from the packet.
- Missing expected trust digest is quarantined with `EXPECTED_TRUST_SNAPSHOT_SHA256_REQUIRED`.
- A cryptographically valid packet carrying its own unapproved trust snapshot is quarantined with `TRUST_ANCHOR_MISMATCH`.
- Reviewer runbook explicitly forbids copying the expected trust digest from the packet being verified.

### Cryptographic ingest and reviewer gates

- External ingest uses the certificate verifier + pinned trust snapshot + independent anchor match before `real_packet_verified=true`.
- Provenance records packet/package/manifest/trust/signature/certificate/signed-payload digests and exact runtime-case contract.
- Workbench `Signature` gate is driven by `signer_trust.valid`.
- Workbench `Trust` gate requires both cryptographic signer trust and `trust_anchor_match=true`.
- Reviewer Action Policy is still the button authority and consumes those same crypto/trust fields; legacy reason-name absence is not sufficient.
- Reviewer GUI wrapper overrides the visual Signature/Trust rows so displayed gate state matches the crypto authority used by the action policy.

### Anti-forgery controller boundary

- `PromotionWorkbenchController.ingest()` requires expected package digest, expected manifest digest and independent expected trust-snapshot digest.
- `record_decision()` no longer trusts a local metadata file merely because `real_packet_verified=true`.
- Before every ledger mutation the controller requires full persisted ingest metadata contract:
  verified ingest status, exact case matrix, immutable raw-evidence flag, frozen baseline, empty ingest reasons, valid import digest, cryptographic signer trust, independent anchor match, complete digest provenance, signer/provenance consistency and exactly seven unique case-report digests.
- A forged minimal local metadata file such as `{ "real_packet_verified": true }` cannot write the decision ledger.
- Click-time Cockpit baseline recheck remains mandatory; drifted `APPROVE` / `REJECT` becomes `INVALIDATE`.
- Ledger append remains exclusive-lock serialized and stale-tail fail-closed.

### Operator workflow

- Vietnamese runbook: `docs/V25.75_WINDOWS_CODEX_EVIDENCE_RUNBOOK_VI.md`.
- Flow: certificate enrollment → record independent trust digest → real Target-Machine 7/7 certification → seven-case export → packet preflight → certificate signing → ingest with independent package/manifest/trust anchors → dual human review.
- Evidence runner requires Windows, a working current Codex CLI, exact seven real case files, release ZIP/manifest, trust store, certificate thumbprint and `cryptography`.
- Preflight does not sign a packet and never creates synthetic evidence.
- Runner local ingest precheck is only a self-consistency check; final reviewer import still requires the independently approved trust snapshot digest.
