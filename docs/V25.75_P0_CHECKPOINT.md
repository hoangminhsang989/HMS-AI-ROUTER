## P0 completed in source

### 1. Exact seven-case Windows/current-Codex contract

Canonical runtime cases remain exactly:

`host`, `codex`, `quota`, `failover`, `lan`, `soak_6h`, `soak_24h`.

The set remains inherited from v25.53 Target-Machine Certification. The exporter only emits seven external case reports from a source report that is already `PASS_TARGET_MACHINE_PRODUCTION_CERTIFIED`, `TARGET_MACHINE_WINDOWS_CODEX_LAN_SOAK`, exact 7/7 and every canonical stage `pass=true`.

### 2. Certificate-only packet signing plus real certificate preflight

- External packets require `WINDOWS_CERTIFICATE_SIGNATURE`; self-declared signer/trust JSON is not accepted.
- `_runtime/HMS_Sign_Digest_With_Certificate.ps1` signs with an RSA private key in `Cert:\CurrentUser\My` without exporting private material.
- `_runtime/HMS_Inspect_Evidence_Certificate.ps1` is a read-only certificate probe.
- `_runtime/HMS_Codex_ExternalWindowsCertificatePreflight.py` independently verifies the probe with `cryptography`.
- Preflight checks exact thumbprint, certificate DER SHA-256, RSA key type/private-key accessibility, validity window, DigitalSignature KeyUsage when present, CA constraints and pseudonymous signer ref.
- Enrollment now requires this preflight before the non-evidence signing challenge and binds the resulting certificate SHA/ref to the preflight result.
- Evidence runner preflight requires the selected certificate SHA-256 to be an ACTIVE trusted pin.
- Trust-store snapshot cannot change between runner preflight and signing.
- The actual certificate used to sign must still match the preflight-selected certificate.

### 3. Independent reviewer-side trust authority

- Packet-carried trust snapshot is never its own trust root.
- `_runtime/HMS_Codex_ReviewerTrustAuthoritySnapshot.py` captures reviewer-side authority from a reviewer-controlled approved trust store, not from the packet.
- Authority contains the approved trust snapshot SHA-256, trust-store generation and ACTIVE pin metadata only.
- `packet_derived=false` and raw packet content is not included.
- Authority has a deterministic `authority_sha256` and default freshness window of 24 hours.
- Missing, stale, future, packet-derived, malformed or tampered authority is rejected.

### 4. DPAPI-backed reviewer local integrity seal

- `_runtime/HMS_Codex_ReviewerLocalIntegritySeal.py` provides purpose-separated HMAC-SHA256 integrity sealing using a machine-scope DPAPI protected local key.
- The key is never exported in the seal.
- Payload tamper, purpose substitution, wrong key and missing/unavailable DPAPI key fail closed.
- Reviewer trust authority is protected by this local seal.

### 5. Sealed verified-ingest state and replay registry

`PromotionWorkbenchController` now stores:

- `verified_ingest_metadata.json`
- `verified_ingest_metadata.seal.json`
- `replay_registry.json`
- `replay_registry.seal.json`
- `reviewer_local_integrity.key.dpapi`

The controller no longer accepts an arbitrary expected trust hash for normal review import. `ingest()` requires a sealed reviewer trust-authority file and derives the expected trust snapshot from that verified authority.

Before every review/ledger mutation the controller requires:

- verified ingest status;
- exact seven-case matrix;
- raw evidence immutable flag;
- frozen Cockpit baseline;
- empty ingest reasons;
- recomputed import digest match;
- cryptographic signer trust;
- independent trust-anchor match;
- sealed reviewer authority match;
- complete package/manifest/trust/certificate/signature/signed-payload provenance;
- signer/provenance consistency;
- exact seven unique case-report digests.

Both verified metadata and replay registry are DPAPI-HMAC sealed. A forged `{ "real_packet_verified": true }`, report tamper, replay-registry tamper, seal loss or unavailable local DPAPI key cannot authorize review.

### 6. Reviewer import entrypoint

`_runtime/HMS_Codex_ReviewerPacketImport.py` is now the reviewer operator path.

It:

- hashes package ZIP and release manifest locally;
- verifies the sealed reviewer trust authority;
- invokes controller ingest;
- reloads the locally sealed verified report;
- requires report and replay seals;
- does not copy the raw packet into reviewer state;
- never promotes, certifies Windows or mutates production score.

Manual reviewer copy/paste of `--expected-trust-snapshot-sha256` is no longer the normal workflow. The low-level ingest module remains a contract/testing layer.

### 7. Reviewer policy / Workbench / GUI authority alignment

- Reviewer Action Policy requires cryptographic signer trust + independent anchor + sealed reviewer trust authority.
- Workbench has a dedicated `reviewer_trust_authority` gate and includes it in final `Trust` eligibility.
- Principal GUI wrapper loads review metadata only through `controller.load_verified_report()`.
- If local metadata/seal verification fails, GUI displays BLOCK and does not start reviewer actions.
- Signature visual gate uses cryptographic verification.
- Trust visual gate uses sealed reviewer authority + anchor match.
- Click-time live Cockpit baseline recheck remains mandatory; drifted `APPROVE` / `REJECT` becomes `INVALIDATE`.

### 8. Fail-closed launcher fallback

Principal launcher path is now:

`HMS_GUI_REVIEW_ENTRY.pyw` → `HMS_GUI_SAFE_FALLBACK.pyw` → legacy core.

The launcher no longer falls directly to `HMS_GUI_ENTRY.pyw` when the principal reviewer wrapper is absent.

`HMS_GUI_SAFE_FALLBACK.pyw` loads legacy core and keeps `AI ROUTER` branding but intentionally does **not** install Promotion Review. Therefore a missing reviewer wrapper cannot expose a promotion screen that reads unsealed raw metadata.

certificate preflight → enrollment → real Target-Machine 7/7 → seven-case export → packet preflight/signing → reviewer trust-authority capture → sealed reviewer packet import → dual human review.
