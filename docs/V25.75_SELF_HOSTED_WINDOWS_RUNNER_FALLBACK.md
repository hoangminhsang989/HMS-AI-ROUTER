Staging is not runner proof. A registered runner is not Windows proof. Only actual execution of the canonical graph on the exact intended PR head can produce CI evidence.

## Critical trust boundary

Self-hosted runners execute workflow code directly on their host. Treat the Windows runner host as privileged project infrastructure.

Rules:

- Do **not** convert the ordinary PR workflow to always-online self-hosted execution.
- Do **not** treat custom labels as authorization boundaries.
- Do **not** leave the runner online outside one frozen qualification window.
- Freeze the exact PR head first; no pushes while the runner is online.
- Review `.github/workflows/v2575-promotion-safety-windows.yml` at that exact head before connecting the runner.
- Never accept unreviewed workflow/source changes while the physical runner is online.
- Stop and remove the runner registration after qualification.
- Never store a runner registration token in the repository, workflow YAML, documentation, `.env`, issue text, or a persistent shell profile.

Private-repository scope reduces public-fork exposure but does not provide VM isolation.
