## Purpose

Close bounded-UAC process targeting trust boundaries without expanding elevation authority and without substituting source/synthetic proof for real Windows validation.

## Defects found by independent review

Two targeting gaps were identified in the prior bounded helper:

1. PID + executable-name revalidation could not distinguish a newly created `Codex.exe`/`ChatGPT.exe` that reused an old PID.
2. `taskkill /T` expanded elevated effects from the validated parent PID to its entire child process tree, including children that had never passed the Codex/ChatGPT allowlist or identity checks.

A further attribution gap was closed by requiring `taskkill.exe` exit code `0`; a non-zero exit can no longer become a successful Close result merely because the original process handle later becomes signaled.

## Runtime hardening

`_runtime/HMS_Codex_WindowsOneShotElevation.py` now requires an expected identity for every elevation target:

- PID;
- canonical supported image name;
- process creation FILETIME represented as `creation_time_100ns`.

The helper:

1. captures supported identities from an opened process object using `QueryFullProcessImageNameW` + `GetProcessTimes`;
2. reopens each target with `PROCESS_QUERY_LIMITED_INFORMATION | SYNCHRONIZE`;
3. rejects name/creation-time mismatch as `WINDOWS_ELEVATION_TARGET_IDENTITY_CHANGED`;
4. keeps the validated process handle open through the UAC prompt and fixed-system `taskkill.exe` execution;
5. verifies termination through the original process handle rather than re-identifying by PID after close;
6. requires `taskkill.exe` exit code `0`;
7. releases process-object handles only after UAC/taskkill completes or fails.

Holding the process-object handle is the PID-reuse barrier: the PID cannot be recycled while that process object remains referenced.

Elevated arguments are now limited to exact validated targets:

- repeated numeric `/PID <pid>` arguments;
- `/F`;
- **no `/T` tree kill**.

The helper still uses only the fixed system `taskkill.exe`, preserves the 32-PID bound and one-shot token, and introduces no PowerShell/cmd/generic elevated command path.

## Caller authority audit

`_runtime/HMS_Codex_WindowsElevationCallerAudit.py` statically audits all runtime Python/PYW files that reference `elevated_close_supported_processes`.

It requires:

- GUI and bounded-harness callers to be present;
- every helper call to provide explicit `expected_identities=...`;
- direct-import aliases to remain auditable;
- dynamic `getattr(..., "elevated_close_supported_processes")` access to be rejected;
- dynamic `**kwargs` not to substitute for the explicit identity argument.

The Windows workflow now compiles and executes this audit as a dedicated required proof step.

## GUI / official-auth lifecycle

`_runtime/HMS_GUI_RECOVERY_ENTRY.pyw` captures process identities rather than PID-only lists for UAC-eligible recovery.

For official-auth switching:

- same PID + same image + same creation time = original client still survives;
- same PID + same allowed image but different creation time = a new process, not the original client;
- identity discovery failure returns `IDENTITY_DISCOVERY_FAILED` and is non-elevatable;
- UAC targets only the surviving original identity map;
- post-commit auth success remains preserved if identity/UAC close fails.

## Validation / session bundle

`_runtime/HMS_Codex_WindowsUACRecoveryValidation.py` uses identity-bound target discovery and passes expected identities into both first attempt and same-token replay.

`_runtime/HMS_Codex_WindowsUACValidationBundle.py` requires:

- identity binding ready at session init;
- identity binding observed in both Cancel and Close case reports;
- Close evidence to report `pid_reuse_blocked_by_open_handles = true`;
- the existing exact Cancel/Close verdicts, replay block, host/source/session binding, effect boundary and positive close count.

`_runtime/HMS_Run_UAC_Validation.ps1` now fails immediately if those identity guards are missing and requires the final pair to declare identity binding.

The pair remains recovery validation only; it is not canonical production evidence.

## Adversarial simulator

`_runtime/HMS_Codex_WindowsRecoveryAdversarialSimulator.py` uses a deterministic synthetic PID range away from `os.getpid()` and covers:

- same-name PID reuse with changed creation time;
- different-image PID substitution;
- missing/malformed identity binding;
- duplicate/current/invalid and 32/33 PID bounds;
- exact numeric taskkill arguments and explicit absence of `/T`;
- policy unknown/not-requested/restart-disabled;
- identity-discovery failure;
- old/new process-incarnation lifecycle;
- UAC one-shot/replay boundaries;
- redaction/classification and quiet background behavior;
- explicit proof that the simulator itself never enumerates real processes, opens real process handles or invokes real UAC/taskkill.

The Windows workflow also executes the simulator as a dedicated proof step rather than relying only on its child invocation from the bounded harness.
