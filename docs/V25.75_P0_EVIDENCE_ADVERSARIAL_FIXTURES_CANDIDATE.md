## Independent-review defects closed

### 1. Version laundering

The historical target-machine certification engine remains `_runtime/HMS_Codex_TargetMachineCertification.py`, version `25.53`, schema 1. It is preserved unchanged.

The v25.75 chain now accepts production source evidence only through `_runtime/HMS_Codex_TargetMachineCertificationV2575.py`, which emits `version = 25.75`, `schema_version = 2` only when the legacy seven real stages pass and the exact release identity is bound.

A v25.53 report cannot be relabeled as v25.75 downstream.

### 2. Release-artifact splicing

The v25.75 target wrapper requires one exact manifest/filesystem/ZIP identity:

- manifest product exactly `HMS-AI-ROUTER`;
- manifest version exactly `25.75`;
- valid `file_count`, safe paths, sizes and SHA-256 values;
- every manifest file must exist on the target filesystem and match size/SHA-256;
- every manifest file must exist inside the ZIP and match size/SHA-256;
- ZIP file set must equal manifest `files[]` exactly;
- at most one enclosing ZIP root directory may be normalized;
- extra/unmanifested ZIP members are rejected;
- traversal, absolute paths, Windows drive/ADS forms, trailing dot/space components and case-insensitive Windows path collisions are rejected;
- mandatory critical certification/runtime/evidence files must be present;
- production binding covers the full manifest, not only the critical subset.

The resulting source certification records the exact package ZIP SHA-256 and release-manifest SHA-256.

### 3. Source/case provenance substitution

`HMS_Codex_ExternalWindowsCaseReportExporter.py` accepts only an exact v25.75/schema-2 artifact-bound target certification and preserves:

- original source capture time;
- exact source certification report SHA-256;
- exact source package ZIP SHA-256;
- exact source release-manifest SHA-256.

All seven canonical case reports carry those bindings.

`HMS_Codex_ExternalWindowsEvidenceRunner.py` hashes source/package/manifest during preflight, re-reads and re-hashes them before packet creation, rejects post-preflight mutation/swap, requires all seven case reports to share the same source/capture/artifact identity, and signs `source_artifact_binding` into the packet.

`HMS_Codex_ExternalWindowsReviewPacketIngest.py` requires the signed artifact-binding schema and requires packet-level and all per-case source/package/manifest digests to agree. Existing exact-case, freshness, replay, Cockpit-baseline, certificate and independent signer-trust gates remain fail-closed.

### 4. Reviewer-side release self-attestation

Independent review found that reviewer import previously hashed whichever package ZIP and manifest the caller supplied and used those hashes as `expected_*`. That was independent from the packet signature but not independent from the selected release artifacts.

`_runtime/HMS_Codex_ReviewerReleaseAuthority.py` now provides a separate reviewer-side release identity authority. It accepts only explicit reviewed inputs:

- package ZIP SHA-256;
- release-manifest SHA-256;
- source commit SHA;
- source tree SHA.

Authority invariants:

- `input_mode = EXPLICIT_REVIEWED_DIGESTS`;
- `packet_derived = false`;
- `local_artifact_hashed_at_capture = false`;
- `raw_packet_included = false`;
- `private_material_exported = false`;
- digest/source formats and freshness are validated;
- authority is sealed using reviewer CurrentUser DPAPI/HMAC;
- persistence uses unique temporary-file + `os.replace` semantics.

The authority cannot be created by silently hashing the local package at capture time.

### 5. Canonical reviewer import and direct-controller bypass

`HMS_Codex_ReviewerPacketImport.py` now requires both:

1. independent reviewer signer/trust authority;
2. independent reviewer release identity authority.

Before ingest, local package/manifest hashes must equal the explicit release-authority digests. The controller then verifies the same release authority again using the reviewer-local DPAPI key.

`HMS_Codex_WindowsPromotionWorkbenchController.py` is the central persisted-state authority and now requires `release_authority_path` on ingest. It persists both reviewer authorities into the locally sealed verified report and `_verified_report_gate()` requires:

- valid sealed signer/trust authority;
- valid sealed release authority;
- release authority non-packet-derived and non-self-hashed;
- valid source commit/tree refs;
- release package/manifest digests equal packet provenance;
- source artifact binding schema/package/manifest equal packet provenance;
- case source report/package/manifest provenance complete and consistent.

Therefore direct `controller.ingest()` cannot bypass release authority. Direct `record_decision()` / `record_review_action()` also cannot bypass it because they reload the full sealed report gate before ledger mutation.

### 6. Promotion policy/workbench/GUI release gate

The following now require `reviewer_release_authority` in addition to the existing signer/trust authority:

- `HMS_Codex_PromotionReviewerActionPolicy.py`;
- `HMS_Codex_PromotionGUIActionContract.py`;
- `HMS_Codex_WindowsPromotionReviewWorkbench.py`;
- `HMS_GUI_REVIEW_ENTRY.pyw`.

Missing, unsealed, packet-derived, self-hashed or artifact-mismatched release authority blocks reviewer actions and promotion eligibility.

The principal launcher remains recovery → sealed review wrapper → guarded GUI. The review wrapper loads the verified report through the controller seal gate rather than trusting raw JSON.

### 7. Decision-ledger package-version laundering

`HMS_Codex_WindowsPromotionDecisionLedger.py` previously stored `package_version` supplied by the caller while only the record's top-level authority version was fixed.

The ledger now fail-closes unless `package_version == 25.75` in:

- decision construction;
- existing-ledger validation;
- append precondition;
- evaluation.

A caller cannot write/evaluate a valid review epoch under a different package-version label.

### 8. Orchestrator contract repair

`HMS_Codex_WindowsEvidenceOrchestrator.py` now:

- passes the required original `source_certification_report` to operator preflight;
- exposes source certification/package/manifest diagnostics;
- supports read-only reviewer release-authority status;
- captures release authority only from explicit reviewed package/manifest/source commit/tree inputs;
- passes both reviewer authorities to canonical packet import;
- retains non-production/no-auto-certification boundaries.
