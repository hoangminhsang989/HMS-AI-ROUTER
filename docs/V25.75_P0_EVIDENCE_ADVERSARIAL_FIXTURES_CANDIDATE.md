## Purpose

Harden the canonical seven-case external Windows/current-Codex evidence chain against contradictory certification metadata, freshness laundering, source substitution, **version laundering**, and **release-artifact splicing**. Synthetic/source proofs remain non-production and do not replace real target evidence.

## Independent-review defects closed in this candidate

### 1. Version laundering

The historical target-machine certification engine is still `HMS_Codex_TargetMachineCertification.py`, version `25.53`, schema 1. The previous v25.75 exporter did not require the source report version and emitted v25.75 case reports. That allowed a valid older certification to be relabeled downstream.

The historical v25.53 engine is preserved unchanged. A new v25.75 wrapper is the only accepted source for v25.75 external evidence.

### 2. Artifact splicing

The historical target certification did not bind a release package ZIP or release manifest, while the external packet runner accepted those artifacts independently. Therefore runtime certification A and package B could be combined without a cryptographic/content link.

The v25.75 chain now binds one exact release identity from target certification through exporter, packet signing and ingest.

### 3. Partial package verification

An initial v25.75 artifact-binding candidate verified the whole ZIP digest but content-checked only a critical subset. Independent committed-byte review found that an unmanifested extra ZIP member could still be bound. The current candidate now requires an **exact manifest ↔ target filesystem ↔ ZIP file set**.

## v25.75 target certification wrapper

`_runtime/HMS_Codex_TargetMachineCertificationV2575.py`:

- keeps the historical v25.53 seven-stage engine unchanged;
- emits top-level `version = 25.75`, `schema_version = 2` only through the new wrapper;
- requires the legacy engine to PASS the exact real seven stages;
- requires artifact binding schema `HMS_V25_75_TARGET_ARTIFACT_BINDING_V1`;
- requires release manifest product exactly `HMS-AI-ROUTER` and version exactly `25.75`;
- validates manifest `file_count`, unique safe relative paths, sizes and SHA-256 values;
- rejects `.` / `..` / absolute/path-escape manifest entries;
- verifies **every** manifest file on the target filesystem by path, size and SHA-256;
- requires the ZIP file set to equal the manifest file set exactly (one optional enclosing package-root prefix is normalized by exact mapping; ambiguous mappings fail);
- verifies every ZIP file by path, size and SHA-256 against the same manifest;
- rejects missing files, changed files, unmanifested ZIP files, duplicate/ambiguous paths and tampering;
- records exact `release_manifest_sha256` and `package_zip_sha256` only after that binding;
- preserves eight certification/evidence files as mandatory critical entries, but production binding covers the full manifest, not just the subset;
- reports the historical engine version separately; it never rewrites a v25.53 report into v25.75.

The release manifest itself is treated as external authority and is not required to self-list. ZIP content must equal manifest `files[]`; an unlisted manifest copied into the ZIP is therefore rejected.
