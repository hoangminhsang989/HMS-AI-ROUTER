## Changelog claim versus exact source

The v1.3.29 changelog groups four API Service conversation capabilities together: HTTP/SSE or Responses WebSocket transport, reasoning replay across turns, Multi-Agent V2 workloads, and an expanded Codex model catalog.

Exact release-to-release source comparison narrows that claim:

- Responses WebSocket is already present in v1.3.28 (`GET /v1/responses` and the Responses WebSocket handler).
- `reasoning.encrypted_content` normalization/replay support is already present in v1.3.28 `codex_protocol.rs`.
- `multi_agent_version: "v2"` metadata is already present in the v1.3.28 embedded Codex client model catalog.
- Therefore those three capabilities must not be classified as newly introduced by v1.3.29.

## Actual source delta: managed model catalog expansion

The material v1.3.29 source delta in this tranche is the managed Codex catalog authority.

In v1.3.28:

- the embedded catalog contains a top-level `model_overrides` array;
- `managed_codex_model_ids()` reads only `model_overrides`;
- no fallback to the full `models` array exists.

In v1.3.29:

- the embedded catalog no longer contains `model_overrides`;
- `managed_codex_model_ids()` first checks overrides, then falls back to the full `models` array;
- the full-catalog fallback is bounded to models with `use_responses_lite=true` and excludes hidden models;
- the catalog carries additional model metadata including apps/plugin usage-instruction flags and Node REPL policy fields.

This is the exact-source basis for classifying the v1.3.29 change as **managed model catalog expansion / catalog metadata expansion**, not as first introduction of Responses WebSocket, reasoning replay, or Multi-Agent V2.
