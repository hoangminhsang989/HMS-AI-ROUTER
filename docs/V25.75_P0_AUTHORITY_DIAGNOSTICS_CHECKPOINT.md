## Delivered

### 1. Read-only reviewer authority status command

`_runtime/HMS_Codex_WindowsEvidenceOrchestrator.py` now exposes:

`reviewer-authority-status`

The command verifies the existing reviewer trust authority through the existing sealed-authority verifier and CurrentUser-DPAPI-backed local integrity key, then reports:

- `AUTHORITY_FRESH`;
- `AUTHORITY_RENEW_SOON`;
- `BLOCKED_FAIL_CLOSED` for stale/invalid/unavailable integrity state;
- `created_utc`, `expires_utc`, `remaining_seconds`;
- trust-store generation, active pin count and local seal validity;
- `renewal_recommended` / `renewal_required`.

The status path is read-only. It does not recapture authority, import a packet, mutate reviewer trust store, copy raw packet, sign evidence, execute live Codex, certify Windows or mutate production score.

### 2. Source-proof false-negative remediation

The existing orchestrator source proof previously searched the complete source text for the forbidden token `evidence_runner.build_packet`. Because the proof expression itself contained that literal token, the check could self-match and fail even when `_operator_preflight()` did not call the builder.

The proof now scopes checks to the relevant function bodies:

- `_operator_preflight`;
- `_reviewer_authority_status`;
- `_reviewer_import`.

This removes the self-match while strengthening the read-only/no-mutation assertions for the new status command.
