## Root cause in v1.3.28

The v1.3.28 account-window query contract contains three identity inputs:

- local `account_id`;
- `official_account_id`;
- account email.

The v1.3.28 runtime backfills official account IDs and, whenever `official_account_id` is present, account-window aggregation matches the log row by official ID instead of the local Cockpit account ID.

That is unsafe for Team/Workspace accounting because multiple local member records can share one upstream official `account_id`. Two local members with the same Team ID can therefore receive the same aggregated request/token window total.

## v1.3.29 identity correction

v1.3.29 changes the accounting identity boundary:

- Rust and TypeScript account-window query contracts remove `official_account_id` / `officialAccountId` and account email inputs;
- the window query is keyed by local `account_id` only;
- SQL filters `request_logs` using `account_id IN (...)`;
- row-to-query matching requires exact local `row_account_id == requested_account_id`;
- upstream source explicitly states that request-log `account_id` is the local Codex account ID and that a Team/Workspace official account ID cannot be used as the local statistics key.

The upstream regression test creates separate local members with 11 and 22 input tokens and asserts the resulting account-window totals remain 11 and 22 respectively.

## Important scope correction

v1.3.29 does **not** remove the upstream official account ID from request-log storage. The `official_account_id` column and population path remain available as metadata.

The material source change is narrower and safety-relevant: **official account ID is no longer the account-window aggregation authority; Cockpit local account ID is.**
