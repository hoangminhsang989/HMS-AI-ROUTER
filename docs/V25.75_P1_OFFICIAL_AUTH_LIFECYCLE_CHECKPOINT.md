# HMS-AI-ROUTER — v25.75 P1 Official Auth Client Lifecycle Recovery Checkpoint

Date: 2026-08-24

## Scope

This increment closes the remaining source-side official-auth client lifecycle recovery gap without changing the PowerShell auth transaction semantics and without parsing human-readable restart messages as authority.

The GUI recovery wrapper now derives a structured `client_lifecycle` result from two independent sources:

1. structured router settings (`CodexLaunchAfterAuthSwitch`, `RestartCodexOnSwitch`);
2. supported Codex/ChatGPT PID identity observed before and after the official auth switch.

## Structured policy authority

The wrapper first uses already-loaded GUI `settings_data` when available.

Because the Settings page is lazy-loaded, it otherwise performs a read-only `get_settings` backend call immediately before the user-requested official auth switch. If the two required boolean values cannot be obtained as booleans, policy state becomes `POLICY_UNKNOWN` and UAC remains disabled.

No arbitrary restart message is parsed to determine elevation eligibility.

## PID identity lifecycle derivation

Before the original official auth transaction starts, the wrapper records the currently running supported client PIDs (`Codex.exe` / `ChatGPT.exe`).

After a successful auth transaction:

- `NOT_REQUESTED`: `CodexLaunchAfterAuthSwitch=false`; no elevation is permitted.
- `RESTART_DISABLED`: launch-after-auth is enabled but `RestartCodexOnSwitch=false`; user policy is respected and no elevation is permitted.
- `POLICY_UNKNOWN`: required structured settings are unavailable; fail closed with no elevation.
- `OK`: restart policy is enabled and none of the original client PIDs remain. New replacement client PIDs are allowed and are not treated as failure.
- `CODEX_RESTART_REQUIRED`: restart policy is enabled and one or more original supported client PIDs are still alive after the successful auth transaction.

Only the last state can expose the one-shot UAC action.

## One-shot UAC behavior after successful auth commit

When `CODEX_RESTART_REQUIRED` is derived:

1. only the surviving **original** Codex/ChatGPT PIDs are eligible targets;
2. the existing one-shot operation token is checked and consumed before UAC;
3. the fixed `System32\taskkill.exe` helper revalidates those PIDs;
4. after a successful close, HMS retries the same official auth target through the original transactional switch implementation so normal verification/restart behavior remains authoritative;
5. manual retry is bounded by the existing recovery retry limit;
6. UAC cancellation or failure does not rewrite the already-committed auth switch as `ok=false`.

If UAC fails or the operator cancels after auth already committed, the UI reports that auth changed successfully but the client lifecycle still requires manual close/reopen.

## Safety invariants

- No generic executable elevation.
- No PowerShell/cmd arbitrary elevated command path.
- No UAC from human-message parsing.
- No UAC when restart was not requested.
- No UAC when the user disabled restart-on-switch.
- No UAC when structured policy is unavailable.
- No killing newly launched replacement client PIDs merely because they are currently running.
- No auth rollback claim after a post-commit UAC cancellation/failure.
- No background probe dialog.
- No production-score or certification authority.
