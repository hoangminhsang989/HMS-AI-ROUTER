# HMS-AI-ROUTER — v25.75 P1 Session-bound UAC Validation Bundle

Date: 2026-08-24

## Purpose

Bind the two required real-Windows recovery observations — **UAC Cancel** and **UAC Accept + supported-client close** — to one short-lived validation session before the project proceeds to the separate canonical production-evidence gate.

This bundle is operational recovery validation only. It is deliberately **not** a cryptographic production attestation and cannot change Windows certification or the production evidence score.

## Safety model

`_runtime/HMS_Codex_WindowsUACValidationBundle.py` provides five commands:

- `proof` — source/synthetic proof only; safe for CI.
- `init` — read-only target preflight and session creation.
- `run-cancel` — invokes the bounded harness and expects `PASS_CANCEL_AND_REPLAY_BLOCK`.
- `run-close` — invokes the bounded harness and expects `PASS_CLOSE_AND_REPLAY_BLOCK`.
- `verify` — verifies both case reports belong to the same session/host/source build, were captured in Cancel→Close order and retain all non-production boundaries.

A session:

- expires after 4 hours;
- requires the read-only preflight to be READY and a supported Codex/ChatGPT client to be running at session creation;
- stores only a SHA-256 reference derived from Windows `MachineGuid`, never the raw MachineGuid;
- binds the source SHA-256 of the one-shot elevation helper, recovery contract, runtime harness and bundle verifier;
- carries `production_evidence_eligible=false`, `windows_runtime_certified=false` and `production_score_mutation_authorized=false`.

The bundle does not sign evidence, import reviewer packets or call the canonical seven-case certification path.

## Target-machine workflow

From the HMS-AI-ROUTER repository on the authorized Windows target, keep Codex/ChatGPT open and create a dedicated output directory outside production evidence storage.

```powershell
$Out = Join-Path $env:LOCALAPPDATA 'HMS-AI-ROUTER\uac-validation-v2575'
New-Item -ItemType Directory -Force -Path $Out | Out-Null

python _runtime\HMS_Codex_WindowsUACValidationBundle.py init `
  --output (Join-Path $Out 'session.json')
```

The `init` command must return `READY`. It performs no UAC and closes no client.

### Case 1 — Cancel

```powershell
python _runtime\HMS_Codex_WindowsUACValidationBundle.py run-cancel `
  --session (Join-Path $Out 'session.json') `
  --output (Join-Path $Out 'cancel.json')
```

When Windows shows the UAC consent dialog, **cancel it**. The command only passes this case when the harness reports:

`PASS_CANCEL_AND_REPLAY_BLOCK`

The same operation token is replayed inside the same process and must be rejected.

### Case 2 — Accept and close supported client

Ensure a supported Codex/ChatGPT client is running, then:

```powershell
python _runtime\HMS_Codex_WindowsUACValidationBundle.py run-close `
  --session (Join-Path $Out 'session.json') `
  --output (Join-Path $Out 'close.json')
```

Accept the Windows UAC prompt. This case only passes when UAC actually started, at least one validated supported-client PID was closed, and same-token replay was rejected:

`PASS_CLOSE_AND_REPLAY_BLOCK`

### Pair verification

```powershell
python _runtime\HMS_Codex_WindowsUACValidationBundle.py verify `
  --session (Join-Path $Out 'session.json') `
  --cancel (Join-Path $Out 'cancel.json') `
  --close (Join-Path $Out 'close.json') `
  --output (Join-Path $Out 'pair-verdict.json')
```

Required final verdict:

`PASS_BOUNDED_UAC_RECOVERY_PAIR`

The verifier fails closed for session mismatch, host mismatch, source mismatch, missing replay block, missing UAC observation, missing close effect, invalid timestamp ordering, boundary promotion or case-report digest collision.

## CI boundary

GitHub Actions compiles this module and runs only:

```powershell
python _runtime\HMS_Codex_WindowsUACValidationBundle.py proof
```

CI never invokes `init`, `run-cancel`, `run-close` or `verify` against a real client.
