## Final decision provenance hardening

Integration review found that sealed ingest retained strong source/release provenance but the final append-only human decision record previously bound only raw packet + manifest, allowing source/package/reviewer-authority references to be dropped at the final ledger layer.

The integration candidate now requires every decision hash-chain record to bind all six digests:

1. `evidence_sha256` — raw packet SHA-256;
2. `manifest_sha256` — release manifest SHA-256;
3. `package_sha256` — package ZIP SHA-256;
4. `source_certification_report_sha256`;
5. `reviewer_trust_authority_sha256`;
6. `reviewer_release_authority_sha256`.

`build_decision()`, `append_decision()`, ledger validation and `evaluate()` are fail-closed on this full set. Dual-review approvals count only when every provenance reference matches the current sealed ingest authority.

The canonical controller derives these values only from the sealed verified report and its sealed reviewer trust/release authorities. Reviewer actions surface a metadata-only `decision_provenance` summary; raw reviewer identity/salt remain excluded.

The review workbench now requires the same six-reference decision provenance and rejects manifest mismatch. Reviewer action policy and GUI contract also require `source_certification_report_sha256`, so buttons cannot be enabled for a packet that the final ledger would reject.
